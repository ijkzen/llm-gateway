# REQUIREMENTS — 供应商模型级网络代理

## 需求（用户原话）

供应商模型可以单独配置网络代理，因此向上游发送请求时，先检查模型本身是否配置了代理，再检查供应商是否配置了代理，都没有才去直连；用量检查和刷新模型列表只需要关心供应商有没有配置网络代理。

## 范围（Scope）

1. `provider_model` 增加与 provider 同构的模型级代理字段：`proxy_enabled`（布尔）+ `proxy_addr`（HTTP 代理，`http://` 开头、无认证）。
2. 上游转发与模型测速（`test_model`）的代理解析优先级：**模型级 → 供应商级 → 直连**。
   - 模型开启了代理且地址有效 → 用模型代理。
   - 否则供应商开启了代理且地址有效 → 用供应商代理。
   - 都没有 → 直连。
3. 用量检查与刷新模型列表**只认供应商级代理**：现状已是如此，本需求不改变这两条路径的取值（即使某模型配了模型级代理也不影响刷新/用量）。
4. CRUD：创建/更新/响应携带两个新字段；校验规则与供应商一致（开启时地址必填 + `http://` 开头 + 无认证）。
5. 前端：模型「编辑」表单支持开关+地址；只读详情加「网络代理」展示行（开=徽标+地址，关=徽标）。参照 ProviderEditDialog / ProviderDetail。
6. 添加模型（手动/刷新批量导入）**不支持**直接配代理——添加后到详情弹窗编辑。

## 裁剪（ponytail 裁定，均为非目标）

- **不改转发 HTTP 机制**：`upstream::call` 的 CONNECT 隧道 + 按 `代理|scheme://host:port` 隔离的连接池 key 已存在（上个提交），只传不同 `proxy` 参数即可。
- **不新增校验 helper**：复用 `routes/providers.rs` 的 `validate_proxy`。
- **不新造 i18n 文案**：复用 `providers.proxy*` 文案键。
- **不加 `model_proxy` 到 Member / 不缓存换算结果**：代理解析做在装配 Member 时，字段带全、解析一次。
- **用量缓存 / 用量获取 / refresh 路径零改动**（已只认供应商）。
- **不做网络代理的可见性角标 / 批量配置 / 级联语义**：超出需求。
- 备注：`validate_proxy` 目前定义在 `routes/providers.rs`（provider_models 子模块可访问，因同属 routes 树但非 pub）；跨文件可见性在实现时确认，若不可见则提为 `pub(crate)`（一处最小改动，不搬文件）。

## 决策记录（grilling 拍板）

- **配置形态**：开关 + 单地址（与供应商同构两字段）——用户已确认。
- **UI 呈现范围**：编辑态 + 只读态展示行（不加卡片角标）——用户已确认。
- **添加时配置**：不支持，添加后详情弹窗编辑——用户已确认。

## 迁移注意（既有知识）

- `schema_migrations` 生产库残留旧 lg-proxy 方案的 14/15 号段，**新迁移从 19 起编**。
- 新列默认值 `proxy_enabled=0`、`proxy_addr=''`，存量模型行自动回落供应商代理，无需回填。

## 验收口径

- 同一模型成员请求走「模型代理」；未配模型代理的请求按供应商代理/直连（回归现有）。
- 用量抓取、模型刷新在「模型配了代理、供应商没配」时仍直连（不误用模型代理）。
