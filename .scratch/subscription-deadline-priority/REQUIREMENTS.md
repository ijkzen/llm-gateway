# 订阅制窗口「截止日期优先」排序

## 背景问题

虚拟模型订阅制优先策略（策略 0/1 的订阅组）目前按 5小时→日→周→月 窗口的**剩余百分比**逐层排序，仅同层打平时才比该层重置时间（早者优先）。

问题：5小时窗口是滚动窗口，各供应商窗口截止时间不同。两个供应商在各自窗口内使用了相近的额度（剩余百分比相近）时，当前逻辑按剩余百分比细微差异决胜，忽略了截止日期差异——**截止日期靠前的供应商额度应被优先消耗**（否则到期被重置浪费）。

## 新算法（用户拍板）

订阅组内比较 `cmp_quota_remaining(a, b)`：

1. 从 5h 层起逐层检查（5h → 日 → 周 → 月）：双方该层都**有额度**（窗口可用且剩余 > 0）？
   - 是 → **跳过剩余百分比**，改比**更上层**（该层之后的日/周/月）的截止时间链：早重置者优先；一方有截止时间另一方缺失 → 有者优先；都缺失 → 继续往更上层；全链平 → 剩余百分比兜底。
   - 否（某方该层窗口不可用/无额度）→ 该层判平，进入下一层。
2. 兜底（截止时间链全部相同/缺失）：按现有逻辑 5h→日→周→月 剩余百分比逐层比较。
3. 无用量数据的成员排在有数据的后面（现状不变）。

### 已拍板决策

| 决策 | 结论 |
| --- | --- |
| 排序策略 | 截止时间优先（FEFO）：同层都有额度 → 比更上层截止时间，更近者优先 |
| 应用范围 | 所有订阅窗口层统一（5h/日/周/月） |
| 缺截止时间 | 排在可判定者之后 |
| 剩余百分比角色 | 仅作最终兜底（截止链全平/全缺失时） |
| 额度前提不成立 | 判平进下一层（与现有"缺失窗口不判负"语义一致） |
| 前端展示 | 同步生效（共用 `cmp_quota_remaining` 比较器，无需改前端） |

## 范围

- 重写 `src/proxy/usage_rank.rs::cmp_quota_remaining`（保持签名不变），新增额度判定与截止时间比较辅助逻辑，复用现有 `worst_window`（最差剩余窗口口径）与 `cmp_window`（兜底）。
- 重写/扩充 `usage_rank.rs` 单元测试覆盖新算法分支。
- 同步更新 `src/proxy/mod.rs` 与 AGENTS.md 中的排序语义描述。
- Command Code 月窗截止时间补取（用户补充）：`api_key.rs::fetch_command_code` 的 subscriptions 解析增加 `currentPeriodEnd`（现只取 `planId`/`currentPeriodStart`），`parse_command_code_credits` 月窗 resets_at 从硬编码 `None` 改为取周期结束时间；补单测。

## 非目标（ponytail cuts）

- 不做剩余百分比 × 时间衰减的综合分（用户已否）。
- 不做"剩余百分比相近时截止时间插队"的阈值方案（用户已否）。
- 不改 `UsageData`/`QuotaWindow` 类型、不改额度门控（`subscription_usable`/`apply_usage_gate`）、不改按量付费排序（`cmp_balance`）。
- 不改前端（展示端共用比较器自动同步）。
- 不新增配置项。
