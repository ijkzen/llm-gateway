# 修复供应商模型删除后页面不可点击

标签：`ready-for-agent`

## Problem Statement

管理员在供应商模型页面的模型详情弹窗中确认删除后，页面仍被残留的模态遮罩或焦点锁定拦截，无法点击任何控件。

## Solution

删除成功时完整关闭其确认弹窗与模型详情弹窗，使页面恢复正常交互；刷新模型数据的既有行为保持不变。

## User Stories

1. 作为管理员，我希望在确认删除供应商模型后能继续操作供应商模型页面，以便管理其他模型。
2. 作为管理员，我希望删除后能点击供应商的“添加”操作，以便新增模型。
3. 作为管理员，我希望删除的既有成功提示与数据刷新仍然工作，以便确认操作结果。

## Implementation Decisions

- 修复模型详情弹窗及其删除确认弹窗的成功路径状态收敛，确保没有打开状态遗留在页面中。
- 复用现有弹窗组件、删除 mutation 和页面状态，不新增依赖、抽象或 API 变更。
- 修改范围限定为供应商模型删除成功后的前端交互状态。

## Testing Decisions

- 在现有前端页面测试中模拟详情弹窗删除成功。
- 删除后验证用户仍可点击页面上的“添加”按钮并打开相应弹窗；此为外部可观察行为，避免断言 Radix 内部 DOM 实现。
- 复用现有供应商模型页面和弹窗测试的 mock 与交互辅助方式。

## Out of Scope

- 删除 API、级联删除规则、缓存失效逻辑与后端修改。
- 其他弹窗的重构、视觉更新或通用弹窗机制。

## Further Notes

- 最小修复优先：仅消除删除成功路径中的残留模态状态。
