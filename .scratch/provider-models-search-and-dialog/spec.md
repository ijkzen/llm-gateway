# Spec — 供应商模型：供应商开关、搜索与添加弹窗

Status: ready-for-agent

## Problem Statement

管理员在供应商模型页面无法直接启用或禁用某个供应商，需要离开当前任务去其他页面操作。已登记的供应商模型较多时，也无法快速定位某个模型或连续查看多个模型详情。添加模型弹窗把自动刷新导入与手动录入混在同一长页面中，内容过长时标题和操作按钮会随内容移动；手动录入的模型目录候选在用户不再操作该列表时不会自行收起。

## Solution

在供应商模型页面内为每个供应商提供即时启用开关；在页面标题栏右侧提供按供应商模型 ID 检索的结果面板。结果保留所有供应商状态、按供应商分组，点击模型后复用现有详情弹窗且不中断搜索会话。

将添加供应商模型对话框组织为「自动添加」与「手动添加」两个 Tab。对话框以适配视口的固定高度展示，标题与底部操作区域固定，中部内容独立滚动。手动添加的模型目录候选在选中或点击其外部时收起。

## User Stories

1. 作为管理员，我想在每个供应商模型区块直接启用或禁用供应商，以便无需离开模型管理页即可调整供应商可用性。
2. 作为管理员，我想让供应商开关在点击后立即反映新状态，以便快速确认我的操作已被接受。
3. 作为管理员，我想在开关更新失败时看到错误并恢复原状态，以便不会把失败的请求误认为配置已变更。
4. 作为管理员，我想在标题栏右侧输入供应商模型 ID 搜索，以便从大量登记模型中快速定位目标。
5. 作为管理员，我想让搜索只按供应商模型 ID 匹配，以便检索规则稳定、可预期。
6. 作为管理员，我想让搜索结果按供应商分组，以便看清同一模型归属的上游接入实例。
7. 作为管理员，我想让禁用供应商的模型仍出现在搜索结果中，以便核查配置或重新启用前查看详情。
8. 作为管理员，我想点击搜索结果直接打开模型详情，以便不必先在长页面中寻找卡片。
9. 作为管理员，我想在打开和关闭模型详情后继续保留搜索关键词和结果，以便连续检查多个模型。
10. 作为管理员，我想在点击结果面板外部时关闭结果面板，以便在继续浏览页面时消除临时遮挡。
11. 作为管理员，我想在添加模型时明确选择自动添加或手动添加，以便理解不同导入路径并专注当前任务。
12. 作为管理员，我想在自动添加 Tab 中刷新、查看和选择候选模型，以便批量导入上游已公开的模型。
13. 作为管理员，我想在手动添加 Tab 中填写单个模型的配置，以便添加未能由刷新流程获取的模型。
14. 作为管理员，我想让添加弹窗的标题和操作按钮保持固定，以便长候选列表或长表单滚动时始终能识别上下文并完成操作。
15. 作为管理员，我想让手动模型目录匹配结果在选择候选后收起，以便填写后的表单保持清晰。
16. 作为管理员，我想在不选择候选而点击列表外部时收起匹配结果，以便取消联想而不清空已输入内容。

## Implementation Decisions

- 复用 Provider 的既有 `enable` 字段和更新能力；供应商开关只修改该字段，不改变额度门控、连续失败禁用或虚拟模型条目的既有语义。
- 供应商开关使用局部乐观显示：发起更新后立即切换视觉状态；更新失败时恢复来自 Provider 数据的原值并显示现有错误通知；成功后使供应商查询失效并使用刷新后的数据。
- 搜索在前端对已由页面加载的 ProviderModel 集合做不区分大小写的 `providerModelId` 包含匹配。不会请求新 API、不会检索未加载或远端未登记的模型。
- 将搜索命中的 ProviderModel 通过 `providerId` 关联到页面加载的 Provider，并按 Provider 的页面既有排列顺序分组。Provider 是否启用不影响分组是否显示。
- 搜索结果项调用页面既有的模型选中状态与详情对话框，不另建详情页面或第二个模型详情实现。结果面板的可见性与输入关键词分开维护，因此详情对话框的打开/关闭不清空搜索；页面内点击结果面板以外区域时隐藏面板。
- 每个供应商模型区块的标题操作区在现有「添加」按钮左侧增加 Provider 启用开关。开关交互遵循项目已有 Provider 开关的错误处理和通知模式。
- 添加弹窗内部以本地 Tab 状态划分自动添加和手动添加。自动 Tab 承载刷新候选及批量导入；手动 Tab 承载现有 React Hook Form 表单及模型目录联想。切换 Tab 不引入额外持久化状态。
- 添加对话框的内容容器使用固定/受视口约束的高度与纵向 flex 布局：标题和页脚不收缩，中间区域 `flex-1` 且可滚动。现有关闭按钮和对话框可访问性保持不变。
- 手动目录候选在单一弹窗内维护可见状态：选择候选后应用目录默认值并隐藏；对候选面板外部的指针操作也隐藏。点击搜索输入框和候选自身不应被识别为外部操作。
- 所有新增可见文案进入当前 i18n 资源，继续使用项目既有 UI 组件和已安装依赖。

## Testing Decisions

- 测试以用户可观察行为为准，而非组件内部 state 或 CSS 实现细节。
- 在既有 Provider Models 页面测试中覆盖：按模型 ID 搜索、按供应商分组、禁用供应商仍显示、点击结果打开现有详情、详情关闭后关键词和结果保留、面板外部点击收起、供应商开关成功更新及失败回滚。
- 在既有添加模型对话框测试中覆盖：自动/手动 Tab 可切换、两个 Tab 保留各自业务入口、固定区域所需的语义/类结构，以及手动目录候选在选择和点击外部后均收起。
- 复用项目既有 React Testing Library、Vitest、MSW/现有 API mock 以及相邻 provider-model 页面和弹窗测试的断言风格。前端 UI 行为调整不要求新增 Rust 测试。

## Out of Scope

- 不新增后端端点、数据库表、字段或迁移。
- 不提供服务端全文搜索、供应商名称/能力搜索、模糊排序或远端实时模型搜索。
- 不改变 Provider、ProviderModel、虚拟模型、额度门控或连续失败禁用的领域语义。
- 不新增通用搜索/点击外部/弹窗框架，不新增 npm 或 Rust 依赖。
- 不重设计模型详情内容、自动刷新协议或模型目录数据。

## Further Notes

- 使用项目术语：供应商（Provider）为上游接入实例；供应商模型（ProviderModel）为登记在某个供应商名下的具体模型条目；模型目录为手动录入时的内嵌元数据来源。
- 测试切面已由用户确认：页面级交互测试与添加弹窗交互测试。
- 需求精简结论：全部需求可在当前前端数据、详情弹窗、Provider 更新模式和 shadcn/Radix 组件上实现。
