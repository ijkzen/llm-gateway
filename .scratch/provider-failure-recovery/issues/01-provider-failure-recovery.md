# 01: 执行一轮连续失败供应商自动恢复

**What to build:** 提供可直接执行的一轮自动恢复流程：只处理连续失败禁用的供应商；支持用量查询者须先确认仍有可用额度或余额；符合条件者按稳定顺序选择首个供应商模型发送一次真实测试请求；成功后条件性解除连续失败禁用、启用供应商、清零失败计数并恢复级联停用的虚拟模型条目，其他情况保持原状。

**Blocked by:** None (can start immediately)

**Status:** completed

- [x] 仅扫描 `failure_disabled=true` 的供应商，非连续失败禁用状态不受影响。
- [x] `extra.usage=true` 时强制刷新用量，仅明确可用时探测；耗尽、无法判定或抓取失败均保持禁用且不探测。
- [x] 无用量能力时直接探测；供应商模型按主键升序取第一条，无模型保持禁用。
- [x] 每个供应商每轮最多发送一次真实模型测试请求，沿用现有协议、代理、2xx 成功和请求记录语义。
- [x] 探测成功仅在供应商仍为连续失败禁用时原子恢复 `enable` 与 `failure_disabled`，随后清零失败计数。
- [x] 恢复只重开 `cascade_disabled=true` 的虚拟模型条目，管理员手动禁用条目保持禁用。
- [x] 单个供应商失败不会终止整轮；重复执行和过期探测结果不破坏当前状态。
- [x] 业务集成测试覆盖无用量/有用量的成功与失败、耗尽/未知/抓取失败、无模型、多模型稳定选择、状态级联、请求记录及条件恢复。
