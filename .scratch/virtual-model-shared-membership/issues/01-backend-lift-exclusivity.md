# 01: 后端解除互斥映射（迁移 + 管理 API）

**What to build:** 网关管理员可以通过管理 API 把同一个供应商模型加入两个（乃至更多）虚拟模型，两边成员列表各自正确；同一虚拟模型内重复添加同一成员仍被去重。存量库升级后自动不再有互斥约束。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 新迁移（28 号段）将 `virtual_model_item.model_id` 的唯一索引换为普通索引，建表语句同步为普通索引，新旧库 schema 一致
- [ ] 虚拟模型创建/更新不再返回「模型已被其他虚拟模型使用」；模型存在性校验与同虚拟模型内去重保留
- [ ] 唯一索引 SQL 错误兜底文案路径删除
- [ ] 集成测试：同一供应商模型加入两个虚拟模型均成功且成员列表正确（原互斥用例反转）
- [ ] 迁移测试：迁移后无唯一约束、仍有普通索引
- [ ] 备份/级联删除等既有回归全绿
