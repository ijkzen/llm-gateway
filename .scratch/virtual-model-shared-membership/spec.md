# Spec — 虚拟模型共享映射（解除供应商模型互斥归属）

Status: ready-for-agent
Requirements: `.scratch/virtual-model-shared-membership/REQUIREMENTS.md`
Decisions: ADR-0026（取代 ADR-0020 决策 2「互斥映射」）

## Problem Statement

作为网关管理员，我想把同一个供应商模型同时用作多个虚拟模型的成员（例如 `gpt-4o` 同时进 `fast` 和 `smart` 两个虚拟模型），但现在「一个供应商模型最多归属一个虚拟模型」的互斥限制把第二个虚拟模型的候选直接藏掉、API 也拒绝，导致我只能为同一上游模型建重复的供应商模型条目，或放弃复用。

## Solution

彻底移除互斥映射（ADR-0026）：一个供应商模型可不限数量地同时出现在多个虚拟模型下（共享映射）。同一虚拟模型内同一供应商模型仍只出现一次。管理 API、备份导入、前端候选列表三处规则一致；数据库唯一索引换为普通索引兜底查询性能。删除虚拟模型只删其名下条目，其他虚拟模型的归属不受影响。

## User Stories

1. As a 网关管理员, I want to 把一个供应商模型加入第二个虚拟模型, so that 同一上游模型可被多个虚拟模型复用。
2. As a 网关管理员, I want to 在编辑虚拟模型的候选列表中看到已被其他虚拟模型映射的模型, so that 我能有意识地选择共享。
3. As a 网关管理员, I want to 不限数量地共享同一供应商模型, so that 无需在「恰好两个」之类的人为上限间做选择。
4. As a 网关管理员, I want to 同一虚拟模型内仍然不能重复添加同一供应商模型, so that LB 成员权重与顺序无歧义（现状保持）。
5. As a 网关管理员, I want to 导出的备份在另一实例导入时共享成员不被拒, so that 迁移配置与实时 API 规则一致。
6. As a 网关管理员, I want to 导入含同一虚拟模型内重复成员的备份仍被拒绝, so that 组内去重语义不被备份绕过。
7. As a 网关管理员, I want to 删除一个虚拟模型时共享成员在其他虚拟模型中继续存在, so that 删除是局部的、不误伤其他虚拟模型。
8. As a 网关管理员, I want to 停用/启用供应商时其名下全部虚拟模型条目（含多归属行）级联处理, so that 可用性语义与单归属时一致。
9. As a 网关管理员, I want to 成员协议不匹配仍按接口类型级联移除, so that 共享不绕过接口类型校验（ADR-0005 语义不变）。
10. As a 网关管理员, I want to 升级后存量库自动去掉互斥索引, so that 无需手工迁移即可共享。
11. As a 调用方, I want to 共享成员在各虚拟模型中独立参与 LB 选路与 failover, so that 转发行为不受归属数量影响。
12. As a 网关管理员, I want to 请求日志/数据面板按虚拟模型维度统计共享成员, so that 观测口径不因共享而串号（主体键不变）。
13. As a 网关管理员, I want to 用户文档同步说明共享归属, so that 文档与实际行为一致。

## Implementation Decisions

- **数据库**：新迁移（28 号段）把 `virtual_model_item.model_id` 上的唯一索引换为普通索引（保留查询路径索引能力）；建表语句同步改为普通索引，保证新库与存量库 schema 一致。迁移按本仓库 `schema_migrations` 增量模式编写。
- **管理 API**：虚拟模型创建/更新的成员校验保留「模型存在于 provider_model」「同一虚拟模型内去重」，删除「未被其他虚拟模型占用」冲突检查与唯一索引 SQL 错误兜底文案。
- **备份导入**：删除「同一次导入内同一供应商模型不可重复（跨虚拟模型）」校验；保留自然键唯一（供应商名、display_id、api key name）与同一虚拟模型内成员去重。
- **前端**：编辑弹窗候选列表移除「已被其他虚拟模型映射」过滤（页面计算的映射集合与 prop 一并删除）；相关提示文案去掉「被其他虚拟模型占用」表述；「已使用/未使用」Tab 语义不变（仍按当前虚拟模型自身成员划分）。
- **删除语义**：删除虚拟模型只删除其名下虚拟模型条目；「删除即释放成员」表述作废（ADR-0026 决策 3）。
- **不变量保持**：接口类型/协议匹配校验、级联停用/恢复（cascade_disabled）、LB 排序与 failover、统计主体键全部不变——多归属行按各自虚拟模型的条目独立参与。
- **文档**：CONTEXT.md「共享映射」词条、ADR-0026、用户指南成员规则段随实现对齐。

## Testing Decisions

好测试只测外部行为：API 接受/拒绝什么、备份导入成败、候选列表可见性、schema 索引形态；不断言内部函数调用。

四个既有测试缝（用户已确认）：

1. **虚拟模型 API 集成测试**（`tests/virtual_models_integration/members.rs`）：反转 `test_model_can_only_belong_to_one_virtual_model` 为共享成功用例——同一供应商模型加入两个虚拟模型均成功且各自成员列表正确；同虚拟模型内重复添加仍被去重/拒绝。先例：同文件其余 CRUD/校验用例。
2. **备份导入校验测试**（`src/backup.rs` 单元测试）：含跨虚拟模型共享成员的备份 JSON 解析通过；同虚拟模型内重复成员仍报错。先例：既有 backup 校验单元测试。
3. **前端候选列表测试**（`web/src/components/__tests__/virtual-models-dialogs.test.tsx`）：候选列表展示已被映射模型；删除 `mappedModelIds` 相关断言与 prop。先例：同文件 Tab/候选交互用例。
4. **DB 迁移测试**（`src/db/tests.rs`）：迁移 28 后 `virtual_model_item(model_id)` 不再有唯一约束、仍有普通索引。先例：既有迁移补列/索引断言用例。

## Out of Scope

- 「已在他处使用」徽标或共享提示 UI（未请求，不建）。
- 「最多两个」计数上限（备选被否，ADR-0026）。
- 同虚拟模型内重复成员（保持去重）。
- LB/用量/统计逻辑改动（多归属对这些路径透明）。
- 历史请求数据迁移（无归属语义数据需迁移）。

## Further Notes

- 级联删除路径（删供应商模型/删供应商）已按 model_id 删多行 virtual_model_item，天然支持多归属，无需改动但回归通过即可。
- `availability` 级联按 model_id 批量处理条目，多归属行同样命中；若测试暴露单行假设则按共享语义修正。
