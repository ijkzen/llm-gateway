# 数据面板首页「今日」指标 — 需求

## 范围

数据面板首页（`/`，即 `web/src/pages/overview.tsx`）顶部现有 4 张**累计**指标卡
（累计请求数 / 成功率 / 累计 Token / 缓存命中率，数据源 `GET /api/stats/summary` 全量聚合）。
本需求在其下方新增一排 **4 张「今日」指标卡**，指标口径与累计卡完全一致，仅统计窗口从「全历史」变为「今日（截至当前）」。

## 已拍板决策（grill 2026-09-04）

1. **布局**：共 8 张卡片，一行 4 张，上面一行是累计的，下面一行是今日的。
   （副标题语义分组：累计行副标题「全部历史」；今日行副标题「今日」。）
2. **今日时区口径**：与首页现有「调用分析 / Token 分析 / 可靠性分析」三块图表默认「今天」窗口完全一致
   —— 浏览器本地自然日 `[本地今日0点, now]`，复用 `periodBounds("day", 0, now)`（当前周期终点截到 `now`，非明天 0 点）。
   `race-period.ts` 现有语义即「本地今天 0 点 → now」。
3. **卡副标题**：今日卡副标题用「今日」/「Today」（双语，跟随现有 i18n）。
4. **接口形态**：**复用 `/api/stats/summary` 加可选参数**（`startTime`/`endTime`，毫秒时间戳）：
   - 无参数 → 保持现状：全量历史累计（完全向后兼容，前端旧调用不受影响）。
   - 带区间 → 只聚合该区间（半开 `[start, end)`）。前端「今日」卡传本地今日窗口区间。
   - 前端今日卡复用同一 summary query hook，传参数即可，不新增独立端点。

## 非目标（ponytail 裁剪）

- **不做**多区间聚合 API、不做日/月/年通用 summary 窗口参数化重构——只加一个可选时间过滤。
- **不做**后端「今日」固定语义端点（`/summary/today` 之类）——今日边界由前端按本地时区算出后传区间，与全站图表时区口径一致，避免后端出现与时区不一致的第二套语义。
- **不做**今日与累计同卡双值合并布局（用户明确选 8 卡两行）。
- **不做**8 张卡放入可复用「分组卡」抽象——直接在页面网格里放两行现有 `StatsCard`。
- **不改动**任何 `request` 表结构、`charts`/rank/metrics 端点。

## 关键事实与口径

- `request.start_time` 为 UTC 毫秒时间戳；`/api/stats/summary` 现为单条全表 SQL。
- 成功/缓存口径与现有累计卡一致：
  - 请求数 = `COUNT(*)`
  - 成功率 = `SUM(success)/COUNT(*)`
  - 总 Token = `SUM(total_tokens)`
  - 缓存命中率 = 加权 = `SUM(input_cache_tokens)/SUM(input_tokens)`
- 时区：全站统计图表均按浏览器本地时区（`tzOffsetMinutes` 透传）。今日边界沿用同一口径，由前端本地计算，后端只按 UTC 时间戳过滤。

## 验收要点

- 顶部出现 8 张卡：第一行累计（副标题全部历史），第二行今日（副标题今日），值格式与现有 4 卡一致。
- 今日卡的值 = 本地今日 0 点至当前时刻的聚合；累计卡值 = 全历史，**不受**今日卡影响。
- 后端 `/api/stats/summary` 无参数返回与改动前完全一致；带时间参数返回正确区间聚合。
- 前后端测试全绿；前端 lint / cargo fmt / clippy 全绿。
