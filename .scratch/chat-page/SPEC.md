# Spec: 聊天页（chat-page）

标签：`ready-for-agent`

## Problem Statement

管理员在管理后台配置了大量供应商与模型，但想快速试用某个具体模型（看回答质量、看思考过程）时，只能拿着 API Key 去外部工具调 /v1，或受限于虚拟模型的 LB 选路。管理后台内没有一个「选个模型直接聊」的地方。

## Solution

在侧边栏「数据面板」之下新增「聊天」页：上方是左右气泡的聊天记录，下方是输入框；输入框右上角可向上弹出按供应商分组的模型选择浮窗（仅启用项）。对话经新增的会话鉴权 `/api` 聊天端点直连所选供应商模型，复用现有转发管线（协议转换、连接池、request 落库），流式渲染回复与思考过程，思考完毕自动折叠。

## User Stories

1. 作为管理员，我想在侧边栏「数据面板」下看到「聊天」导航项，以便一眼找到试用模型的入口。
2. 作为管理员，我想在聊天页看到上下两块布局（上聊天记录、下输入框），以便符合我对聊天工具的直觉。
3. 作为管理员，我想让我的消息靠右、模型回复靠左，以便一眼区分对话双方。
4. 作为管理员，我想在输入框右上角点开模型选择浮窗，以便发起对话前选定目标模型。
5. 作为管理员，我想让模型浮窗向上弹出（因为输入框在页面底部），以便浮窗不被屏幕边缘截断。
6. 作为管理员，我想让浮窗内模型按供应商分组，以便在熟悉的供应商下快速定位模型。
7. 作为管理员，我想让浮窗只列启用供应商下的启用模型，以免选中必然失败的停用项。
8. 作为管理员，我想让回复以流式方式逐字出现，以便立刻看到模型开始响应。
9. 作为管理员，我想让思考过程在输出时持续展示，以便观察模型推理进展。
10. 作为管理员，我想让思考过程在正文输出后自动折叠，以便不占据阅读空间。
11. 作为管理员，我想能手动展开已折叠的思考过程，以便回看完整推理内容。
12. 作为管理员，我想在发送中点击「停止」，以便中断不想要的生成并保留已输出部分。
13. 作为管理员，我想在一条会话里多轮追问（携带上下文），以便连续调试同一个模型。
14. 作为管理员，我想清空当前对话，以便从头开始测试。
15. 作为管理员，我想让聊天请求计入数据面板统计（request 表），以便统一观测网关全部流量。
16. 作为管理员，我想在模型回复失败时看到错误信息，以便知道是配置问题还是上游问题。
17. 作为管理员，我想让聊天接口受登录会话保护，以便未登录者无法借用网关对话。

## Implementation Decisions

- **导航与路由**：侧边栏在「数据面板」项下新增「聊天」项，路由 `/chat`，页面纳入既有登录守卫。
- **对话链路**：新增 `/api/chat/completions`（POST，Cookie 会话鉴权，复用 `/api/*` 既有中间件），请求体为 `{ providerId, modelId, messages }`；后端按 provider+model 直连上游，内部复用现有转发管线（上游客户端/连接池、四协议请求与流式转换、request 表落库），以 SSE（OpenAI chunk 风格）回传。`model` 字段回填供应商模型 ID。不走虚拟模型路由，不做 failover 重试。
- **流式协议**：响应 SSE data 行复用现有 `chunk_json` 归一结构；思考内容走 `choices[0].delta.reasoning_content`，正文走 `choices[0].delta.content`，结束帧 `finish_reason`。前端用原生 fetch + ReadableStream 解析。
- **思考折叠状态机**：消息对象持有 `reasoning` 与 `content` 两段累计文本；流式期间思考区展开实时追加；当收到首个正文增量或流结束时，若思考已完成则自动折叠为可点击的摘要条（如「思考过程 · N 字」）；点击可在展开/折叠间手动切换。
- **会话状态**：单会话消息列表存于页面组件内存（React state），不落库、不进全局 store；「清空」按钮重置列表与选中模型不变。
- **多轮上下文**：每次请求携带当前会话全部消息（user/assistant 文本，思考内容不回传上游）。
- **模型下拉数据**：复用既有 providers 与 provider-models 查询，前端按 provider 分组过滤 enable。
- **纯文本渲染**：正文与思考内容均按纯文本 + 换行展示，不引入 Markdown 依赖。
- **停止**：前端 AbortController 中断 fetch；已累计内容保留，并标注「已停止」。
- **错误呈现**：请求失败/流中断错误在该条助手气泡内以错误样式展示，不弹全局 toast 轰炸。
- **i18n**：页面文案走既有 i18n 机制（中文为基准）。

## Testing Decisions

- 好的测试只断言外部行为：HTTP 状态、SSE 帧序列、落库结果、页面渲染出的气泡与交互状态，不测内部函数。
- **后端**：复用 HTTP 集成测试接缝（`build_authed_app` + 本地 mock 上游，先例 `tests/proxy_integration.rs`）。覆盖：未登录 401；不存在的 provider/model 404；停用供应商/模型拒绝；流式响应输出 content 与 reasoning_content 帧；请求后 request 表新增一行。
- **前端**：复用 Vitest 组件测试接缝（mock 数据 hooks 与 fetch 流，先例 `web/src/__tests__/`）。覆盖：气泡左右分布；模型浮窗按供应商分组且仅启用项；思考过程流式展示→自动折叠→可手动展开；停止按钮中断后保留已收内容。

## Out of Scope

- 聊天记录持久化、多会话管理（列表/新建/切换/重命名）。
- Markdown/代码高亮渲染（纯文本）。
- 生成参数设置（temperature、max_tokens 等）与系统提示词配置。
- failover 重试、虚拟模型选路接入。
- 聊天记录搜索/导出/一键复制按钮。
- /v1 行为的任何变更、新增协议转换。

## Further Notes

- 四协议转换器已归一输出 `reasoning_content`，后端无需新增思考内容处理能力，只需把既有管线接到新端点。
- request 表落库沿用现有指标口径（ttft/tps 等），聊天流量与 /v1 流量在数据面板中不可区分来源是可接受的（后续需要再加来源标记）。
