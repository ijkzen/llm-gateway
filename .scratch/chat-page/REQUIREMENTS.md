# 聊天页需求（chat-page）

来源：用户原始口述 + grilling 访谈定论（2026-09-06）。

## 范围

1. **导航**：侧边栏「数据面板」之下新增「聊天」导航项，进入 `/chat` 页面。
2. **布局**：上下两块——上方聊天记录（滚动区，用户消息靠右、助手回复靠左的气泡），下方输入框。
3. **模型选择**：输入框区域右上角触发下拉浮窗，**向上弹出**（输入框贴近页面底部）。浮窗内按供应商分组（供应商名做组标题），仅列**启用供应商**下的**启用模型**；选中「某供应商的某模型」发起对话。
4. **对话链路（后端）**：新增 Cookie 会话鉴权的 `/api` 聊天转发端点，请求携带 `provider_id` + `model_id`，后端直连该供应商上游并**复用现有转发管线**（协议转换、连接池、request 表落库/统计、思考内容归一）。鉴权走既有 `/api/*` 会话中间件，不涉及 API Key 明文。
5. **流式输出**：SSE 流式渲染助手回复（纯文本、保留换行）。
6. **思考过程**：`delta.reasoning_content` 流式实时展示；思考完毕（正文开始输出/流结束）**自动折叠**为摘要条，可手动展开回看。
7. **多轮**：单会话内存态，后续请求携带此前全部消息作为上下文。
8. **停止**：发送中可点「停止」，前端中断流（AbortController），已收到的部分保留。

## 非目标（ponytail 裁剪）

- ❌ 不持久化聊天记录（刷新即清空）——用户拍板。
- ❌ 不做多会话列表/新建/切换——用户拍板，单会话 + 清空即可。
- ❌ 不新增前端依赖：Markdown 不渲染（纯文本已拍板）；模型选择用现有 shadcn Popover/DropdownMenu；SSE 解析用原生 fetch + ReadableStream 手写解析（约 30 行），不引入 eventsource-parser。
- ❌ 不做参数设置（temperature/max_tokens 等），后端用管线默认值。
- ❌ 不做失败自动重试/failover UI（直连单模型，失败即展示错误气泡）。
- ❌ 后端不新增协议转换、不改 /v1 行为。
- ❌ 不做聊天记录搜索/导出/复制按钮（浏览器原生选择复制即可）。

## 已确认的事实约束

- 四协议转换器已把上游思考内容归一为 OpenAI 风格 `delta.reasoning_content`，前端只需渲染。
- `/v1/chat/completions` 只认虚拟模型名 + Bearer Key，与「供应商→模型」直选不匹配，故走新 /api 端点。
- 前端已有 `useProviders` / `useProviderModels` / `useVirtualModels` 数据源可复用。
- 聊天请求照常写 request 表（计入数据面板统计）——用户拍板。
