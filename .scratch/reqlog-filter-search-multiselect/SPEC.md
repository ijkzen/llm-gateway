# Spec: 请求日志过滤项关键词搜索 + 多选

Labels: `ready-for-agent`

## Problem Statement

请求日志页的过滤项（虚拟模型、供应商、上游模型、API Key）目前是单选下拉，想同时看几个虚拟模型或几个供应商的日志时只能查多次；选项多时（如上游模型按供应商分组后有几十项）靠肉眼滚动找目标项效率低。

## Solution

4 个选项类过滤项（虚拟模型 / 供应商 / 上游模型 / API Key）改为多选下拉：下拉内顶部提供关键词搜索框过滤选项，选项以复选框列表呈现，顶部提供全选三态复选框行。手动勾满所有选项时自动归一化为「全部」（等价于不过滤，后端不传参）。状态过滤（成功/失败）只有两个值，保留单选不变。

## User Stories

1. 作为管理员，我想在虚拟模型过滤下拉中同时勾选多个虚拟模型，以便一次查看多个虚拟模型的日志。
2. 作为管理员，我想在供应商过滤下拉中同时勾选多个供应商，以便对比多个供应商的调用情况。
3. 作为管理员，我想在上游模型过滤下拉中同时勾选多个模型，以便一次查看若干相关模型的日志。
4. 作为管理员，我想在 API Key 过滤下拉中同时勾选多个 Key，以便一次查看若干 Key 的调用记录。
5. 作为管理员，我想在下拉顶部输入关键词实时过滤选项列表，以便在几十个选项中快速定位目标项。
6. 作为管理员，当我在某过滤项中手动勾选了全部选项时，该过滤项应自动归一化为「全部」（不向下传过滤参数），以便语义上等同于未过滤而非一个"全选集合"。
7. 作为管理员，我想通过全选行（三态复选框）一键勾选/清空当前过滤项的选项，以便减少逐个点击。
8. 作为管理员，多选供应商后，上游模型下拉的选项应为所选供应商模型的并集，以便模型选项与供应商选择保持一致。
9. 作为管理员，当供应商选择变化导致某些已选模型不再可选时，这些失效的模型选择应被自动剔除，以便过滤参数始终合法。
10. 作为管理员，过滤项触发器上应能一眼看出当前是「全部」还是已选了哪些值（数量/名称摘要），以便不用打开下拉即可确认当前过滤状态。
11. 作为管理员，勾选/取消勾选选项后日志表格应立即按新过滤条件刷新，以便即时看到结果。
12. 作为管理员，重置按钮应把所有过滤项（含多选项）恢复为「全部」，以便一键回到默认视图。
13. 作为管理员，单选状态过滤行为保持不变，以便已有使用习惯不受影响。

## Implementation Decisions

- **多选范围**：虚拟模型、供应商、上游模型、API Key 四项改多选；状态（success）保留现有单选 Select。
- **搜索范围**：仅下拉选项内搜索（纯前端、大小写不敏感的子串匹配，匹配展示文本：虚拟模型 displayId、供应商名、模型 ID、API Key 名）；不做日志内容全文搜索。
- **交互形态**：新增通用 MultiSelect 组件（Popover 弹层，引入 `@radix-ui/react-popover` 依赖）：顶部搜索框 + 全选三态复选框行 + 复选框选项列表；触发器显示「全部」或已选摘要（超过一定数量显示「已选 N 项」类摘要）。
- **全选归一化语义**：组件状态为空集合 =「全部」；勾选集合 == 全部选项集合时归一化为空集合（「全部」）。搜索过滤只影响可见选项，不影响归一化判定与全选行的操作对象（全选行作用于当前搜索结果可见集时需保持归一化语义正确——全选行勾选 = 勾选全部选项（归一化为「全部」），取消 = 清空）。
- **级联**：供应商多选 → 上游模型选项 = 所选供应商模型的并集（供应商为「全部」时 = 全部模型）；供应商变化后剔除不再属于任何所选供应商的已选模型。模型分组展示沿用现有按供应商分组结构。
- **查询时机**：勾选/取消即时触发查询（现有 react-query placeholderData 平滑过渡）。
- **后端契约**：`GET /api/request-logs` 的 `vmId`/`providerId`/`modelId`/`apiKey` 参数改为逗号分隔多值（如 `vmId=1,2,3`），后端解析为列表生成 SQL `IN` 过滤；单值形式天然兼容（单元素列表）；空串/空段忽略；参数缺失 = 不过滤。`success` 保持布尔单值。多值数量不做上限（本地管理界面）。绑定参数仍走参数化查询，无注入面。
- **i18n**：新增文案（搜索占位、已选摘要、全选行等）同步补 zh-CN 与 en。
- **域文档**：CONTEXT.md 中请求日志过滤的描述若涉及过滤基数（单值）需同步修正。

## Testing Decisions

- 好的测试只验证外部行为（HTTP 响应、渲染出的 UI 与回调参数），不断言内部实现细节。
- **后端**：扩展 `tests/request_logs_integration.rs`（既有最高层 HTTP 接缝）——逗号分隔多值参数的 IN 过滤正确性、单值兼容、缺省 = 不过滤、脏值（空段）忽略。
- **前端组件**：新增 MultiSelect 独立组件测试——搜索过滤选项、勾选/取消回调、全选行三态、勾满归一化为「全部」。
- **前端页面**：扩展 `web/src/components/__tests__/request-logs.test.tsx`（mock 数据 hooks 的既有先例）——多选交互后传给 useRequestLogs 的过滤参数正确、供应商-模型级联剔除、重置恢复「全部」。

## Out of Scope

- 日志内容（fail_reason 等）全文/模糊搜索。
- 状态过滤多选化。
- 过滤条件持久化到 URL/localStorage。
- 后端多值数量上限、参数格式校验错误码细化。
