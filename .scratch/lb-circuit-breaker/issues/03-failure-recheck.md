# 03: 失败复查——异步实时用量核验

**What to build:** 支持用量查询的供应商成员请求失败后，后台异步对其做一次实时用量核验：确认额度/余额耗尽则立即走额度门控禁用（供应商+子模型级联停用，usage_refresh 在额度恢复后自动恢复），把「缓存过期导致的降级」在本次请求之后就切断；确认充足则不动作（失败已由连续失败计数路径记录）；核验结果回写用量缓存供后续选路使用。同一供应商去重 + 短时节流，核验失败按无数据处理。

**Blocked by:** 02（失败钩子点与 AppState 结构就绪）

**Status:** ready-for-agent

- [ ] 失败后异步触发 fetch_and_store 强制实时抓取并写 DB 缓存；in-flight 去重 + 60 秒节流（纯逻辑有单元测试）
- [ ] 复查判定：耗尽 → 与 apply_usage_gate 相同的禁用动作；充足 → 不动作；不支持用量查询的供应商跳过
- [ ] 核验抓取失败不触发禁用、不影响计数（职责分离）
- [ ] 集成测试：mock 用量接口返回耗尽 → 一次失败后供应商被禁用，额度恢复数据 + refresh_all_usage → 自动恢复（与 failure_disabled 路径区分）；返回充足 → 不禁用
