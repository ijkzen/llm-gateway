# REQUIREMENTS — 请求日志上游模型下拉按供应商分组

来源（用户原话）：「请求日志过滤功能，供应商和上游模型的过滤项，要有联动，选中某个供应商后，上游模型的下拉框里应该就只展示该供应商的模型，另外，该下拉框缺少供应商名称，如果用户不选择供应商的话，根据分不清所选模型到底属于哪个供应商，因为不同的供应商可能提供同样的模型」

## 现状调查（决定范围）

- 请求日志页（`web/src/components/request-logs/RequestLogsTable.tsx`）已有「供应商」「上游模型」过滤项，联动已实现：选供应商后清空模型选择（L355）、模型选项按 `providerId` 过滤（L156-162）。**用户确认该部分已满足，本期不动。**
- 缺口：上游模型下拉选项只显示 `providerModelId` 字符串（L386-390），未选供应商时不同供应商的同名模型重复出现且无法区分。

## Scope

1. 上游模型下拉改为**按供应商分组**展示：`SelectGroup` + 供应商名分组标题（`SelectLabel`），组内列模型（`providerModelId`）。
2. 分组顺序跟随供应商列表顺序；已选供应商时选项只剩一组，逻辑统一、不做特判。
3. 供应商名查找自 `useProviders()` 列表；查不到时兜底 `#${providerId}`。
4. 未选供应商时选中同名模型：保持现状，跨供应商匹配（后端 `model_id` 精确匹配零改动）。

## Non-goals（ponytail 修剪）

- 不换 Combobox / 不加搜索（用户已拍板用分组；模型规模当前不大）。
- 后端 / API / 类型零改动。
- 不做「已选供应商时隐藏分组头」的特判。
- 不动其他过滤项（虚拟模型/状态/API Key）与其他页面。

## 验收

- 未选供应商：模型下拉按供应商分组，同名模型出现在各自供应商组下，一眼可辨归属。
- 选中供应商：模型下拉仍只显示该供应商的模型（分组标题为该供应商）。
- 既有行为不回归：选供应商清空模型、筛选与重置逻辑不变。
- `pnpm lint` / `pnpm vitest run` 全绿。
