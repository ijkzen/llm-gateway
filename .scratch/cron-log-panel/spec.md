# 定时任务日志弹窗：历史日志移到上区 + 日志条目改两行

## Problem Statement

定时任务「执行日志」弹窗里，历史执行记录点开后，该次执行的日志直接内联渲染在被点击的那一行**下方**。这条日志区夹在历史列表内部，把列表撑开、把下面的执行条目推走，阅读体验差；而且列表一滚动，日志就跟着跑。同时，每条日志把「时间 / 级别 / 内容」压在一行里，长内容被挤在一起，不易扫读。用户希望日志展示到弹窗**上面那块区域**，并且把**时间**和**日志内容**分成两行显示。

## Solution

弹窗上区（原「实时日志」面板）变成一个通用日志查看器，有两种模式：

- **实时模式**（默认）：显示正在执行的 run 的实时日志，维持现有全部行为（自动跟随、回到最新、连接状态提示）。
- **历史模式**：点击历史执行列表中的某一行后，上区切换为显示该次执行的日志。头部标题变为「历史执行日志 · <起止时间>」，右侧提供「返回实时」按钮切回实时模式。

历史行不再在行下方展开日志，改为**选中态**：被选中的行背景高亮、左侧箭头为 ▾，未选中为 ▸。

每条日志渲染为两行：第一行「时间 + 级别」，第二行「日志内容」。实时日志与历史日志统一如此。

上区高度由 `h-64` 加大到 `h-80`，把释放出来的阅读空间给到日志本身；下区历史列表占剩余高度并自行滚动。

## User Stories

1. 作为使用定时任务的管理员，我想点击某次历史执行后直接在弹窗上面那块区域看到它的日志，这样日志不会把历史列表撑开、也不会随列表滚动跑掉。
2. 作为管理员，我想让日志显示在固定位置的上区，这样我阅读历史日志时下区的执行列表保持稳定、仍能对照其他执行记录。
3. 作为管理员，我想在上区历史模式下看到「历史执行日志」标题和该次执行的起止时间，这样我能确认自己正在看哪一次执行。
4. 作为管理员，我想在上区点一下「返回实时」就回到实时日志，这样我在临时查看历史后不需要重新打开弹窗。
5. 作为管理员，我想在查看历史日志期间实时日志继续在后台接收，这样我切回实时时不会漏掉期间产生的日志。
6. 作为管理员，我想在一次新执行开始时上区不要自动跳走，这样我正在读的历史日志不会被打断。
7. 作为管理员，我想在任务正在执行、实时日志正在滚动时也能点开历史执行，这样我不必等它跑完才能查上一次的结果。
8. 作为管理员，我想被点开的那条历史执行整行高亮、左侧箭头朝下，这样我一眼能看出当前在上区看的是哪一次执行。
9. 作为管理员，我想点击已选中的那一行不再在下面展开日志，这样历史列表保持紧凑。
10. 作为管理员，我想每条日志的时间单独占一行、内容单独占一行，这样长日志内容有完整宽度、容易扫读。
11. 作为管理员，我想级别（INFO/WARN/ERROR）和时间显示在同一行并保留颜色，这样我能快速定位错误行，同时时间与级别这类元信息不会占掉内容行。
12. 作为管理员，我想实时日志也是「时间+级别 / 内容」两行，这样实时与历史的排版一致，不需要切换阅读习惯。
13. 作为管理员，我想历史模式下某次执行没有输出日志时看到明确空态文案，这样我知道不是还在加载。
14. 作为管理员，我想历史模式下的日志仍在加载时看到加载提示，这样我知道数据还在路上。
15. 作为管理员，我想上区在历史模式下不再显示实时专属的重连提示，这样界面不会出现与当前内容无关的状态。
16. 作为管理员，我想切换定时任务（换一个 job）时上区自动回到实时模式，这样切换后看到的是当前任务的实时状态而不是上个任务留下的历史查看态。
17. 作为管理员，我想关闭弹窗后重新打开时上区回到实时模式，这样重新打开看到的是当下的实时日志。
18. 作为管理员，我想日志量大的那次执行也能在上区正常滚动查看，这样上区加大后的高度能真正用起来。
19. 作为管理员，我想上区之外的历史列表信息（状态徽章、起止时间、日志条数、截断标记）保持不变，这样我仍然能在列表层面对比各次执行。
20. 作为管理员，我想中英文界面都能看到新增文案（历史执行日志 / 返回实时）的对应翻译，这样界面语言一致。

## Implementation Decisions

### 改动面

单一前端组件及其测试与 i18n 文案。后端、API、SSE 事件契约、数据模型均不变。

### 状态与模式派生

- 现有 `expandedRunId`（`string | null`）语义由「展开哪一行」变为「上区正在查看哪次历史执行」，重命名为 `selectedRunId`。
- 不新增 mode 枚举或日志来源抽象：`selectedRunId === null` 即实时模式，非 null 即历史模式，模式由该状态派生。
- 选中的 run 元信息从已加载的 runs 列表按 `run_id` 查找得到（`runs.find(...) ?? null`），不额外请求。
- 历史日志数据源复用现有 `useCronJobRunLogs(name, runId)`（顶层无条件调用，靠其 `enabled` 控制是否请求），不新增 hook。
- 重置时机：`job.name` 变化时（保留现有行为）与弹窗关闭时（`open` 变为 false）均重置为 `null`（回到实时模式）。

### 上区头部

- 实时模式：头部保持现状（标题「实时日志」、运行中 run 的开始时间、「执行中…」、重连中/重连失败提示、刷新按钮）。
- 历史模式：头部标题改为「历史执行日志」，其后附 `起止时间`（`formatDateTime(started_at) ~ formatDateTime(ended_at)`，`ended_at` 为空时用 `—`）；右侧提供「返回实时」按钮，点击将 `selectedRunId` 置为 `null`。
- 历史模式头部**不显示**状态徽章与日志条数（与被选中的历史行重复，经 ponytail 提案由用户确认砍掉）；实时专属的重连/刷新提示在历史模式下一并不显示。
- 复用现有 `formatDateTime` 与按钮组件；「返回实时」用现有 Button 组件的次级/描边样式与 `sm` 尺寸。

### 上区内容

- 实时模式：保持现状（无执行中的 run 时显示空态；否则渲染 `LogLine` 列表，结束后追加运行汇总行；自动跟随与「回到最新」按钮仅在此模式生效）。
- 历史模式：渲染 `useCronJobRunLogs` 的结果——加载中显示加载文案；有日志则渲染 `LogLine` 列表；空则显示「该次执行未输出日志」。
- 历史模式不做自动跟随、不显示「回到最新」按钮、不显示实时专属的结束汇总行。日志体自身可滚动。
- 滚动容器与自动跟随逻辑（`liveRef` / `autoFollow` / `handleScroll` / `scrollToLatest`）仅服务实时模式；切到历史模式时不影响实时缓冲。

### 日志条目布局

- `LogLine`（memo）由单行 flex 改为两行：第一行 flex 排列 `时间`（原格式化与灰色样式）与 `级别`（原 `w-12` 固定宽与颜色映射），第二行是 `内容`（保留 `whitespace-pre-wrap break-all`）。
- 实时与历史共用该组件，两处同时生效。
- 保留 memo 与现有键（`log.seq`），不改数据结构。

### 历史执行行

- 移除行下方的内联日志区（连同其加载/空态分支）。
- 左侧箭头由「展开态」改为「选中态」：`selectedRunId === run.run_id` 时显示 ▾ 且行背景高亮，否则显示 ▸。
- 行内其余内容（状态徽章、起止时间、日志条数、截断标记）与排版不变；行仍是整行可点按钮，点击行为变为「选中该 run」（再次点击同一行是否取消选中由实现按最小改动决定，至少必须支持通过「返回实时」切回）。
- 按钮保留可访问语义：以 `aria-pressed` 暴露选中态。

### 布局高度

- 上区由 `h-64` 改为 `h-80`（保持 `shrink-0`）。
- 下区历史列表保持 `flex-1` + `min-h-0` 自行滚动。
- 弹窗仍受 `max-h-[85vh]` 约束；标题栏固定、不参与滚动，符合仓库弹窗规范。

### i18n

- 在 cronJobs 段新增两个键（中文与英文同步）：历史执行日志标题、返回实时按钮文案。
- 历史模式空态复用现有「该次执行未输出日志」键，加载态复用现有通用加载键。
- 现有「展开」语义专用的键（如有）若无引用则一并清理，避免残留死键。

## Testing Decisions

- **好的测试只断言外部可见行为**：渲染出的文案、DOM 结构可见状态（哪个区域的日志、头部标题、行高亮/箭头、日志行的两行结构），不断言内部 state、组件名或 class 细节（除非 class 是唯一可观察的选中态信号，此时优先用可访问属性如 `aria-pressed`）。
- **测试模块**：`CronJobLogsDialog` 整组件（唯一实现单元）。
- **测试缝（用户已确认）**：
  1. 组件级渲染断言——沿用现有测试文件的做法：mock 数据 hooks（runs / runLogs）、用 MockEventSource 驱动 SSE 事件、`fireEvent` 模拟点击，断言 DOM。这是现有唯一缝，不新增。
  2. i18n 键集合一致性测试自动覆盖新增文案的 zh/en 同步，无需额外用例。
- **需覆盖的行为**：点击历史行后日志出现在上区且不再出现在行下方；上区头部切换为历史模式（标题 + 起止时间 + 返回实时）；点「返回实时」切回实时内容；历史模式空态；两行布局（时间与级别在同一行、内容在下一行）；选中行高亮/`aria-pressed`；实时日志仍是两行布局；实时模式的既有行为（快照、去重、追加、自动跟随、重连提示）不回归。
- **既有用例调整**：现有「渲染历史执行列表并可展开查看日志」用例按新交互重写；其余实时相关用例应保持通过（若因两行布局导致取文本方式变化，按外部可见行为调整选择器，不放宽断言）。

## Out of Scope

- 后端、API、SSE 事件契约、数据模型、数据库的任何改动。
- 实时日志的自动跟随、回到最新、重连退避等既有行为的改动。
- 上区历史模式新增状态徽章 / 日志条数 / 截断提示（已明确砍掉）。
- 日志搜索、过滤、高亮、导出、复制、行号、时间戳格式变更等新能力。
- 上区的拖拽调高、用户可配置高度、记忆每用户偏好。
- 历史列表的虚拟滚动或分页（仍为最近 30 次）。
- 在历史选中态之外新增键盘导航/上下键切换执行的交互。

## Further Notes

- 上区加大到 `h-80` 后，在很矮的视口（约 500–600px 高）里下区历史列表可用高度会明显变小；这是用户为「日志有更多空间」接受的取舍，本次不引入自适应高度或响应式高度方案。若后续有反馈再单独讨论。
- 需求与两轮 grilling 的 11 项拍板、ponytail 的一项裁剪记录见同目录 `REQUIREMENTS.md`。
- 完成后需通过前端门禁：`pnpm lint`（biome，tab/双引号/100 列）与 `pnpm vitest run` 全绿；本次不涉及 Rust 侧，`cargo` 门禁不受影响。
