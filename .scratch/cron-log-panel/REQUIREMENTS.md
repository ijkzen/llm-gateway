# 定时任务日志弹窗：历史日志移到上区 + 日志条目改两行

## 需求原文（用户原话）

> 稍微改一下定时任务历史执行记录日志的显示方式。现在日志是直接显示在历史记录行下面的，我希望展示到上面区域。时间和日志内容分开展示：时间一行，日志内容一行。

## 现状（已核实）

组件 `web/src/components/cron-jobs/CronJobLogsDialog.tsx`（283 行），弹窗分上下两块：

- **上区**「实时日志」：固定 `h-64`，头部显示标题 + 运行中 run 的开始时间 / 重连状态，日志体由 SSE（`useCronJobLogStream`）驱动，带自动跟随与「回到最新」按钮。非流式的运行结束汇总行也在上区底部。
- **下区**「历史执行（最近 30 次）」：每行 = 箭头 + 状态徽章 + 起止时间 + 日志条数；点击行 → 该次执行的日志**内联渲染在该行下方**（`useCronJobRunLogs` 懒加载），箭头在 ▸/▾ 间切换。

日志条目 `LogLine`（memo）单行 flex：`时间 | 级别(w-12) | 内容`。实时与历史共用该组件。

## 范围（用户逐项拍板）

### 1. 历史日志改到上区

- 点击历史执行行 → **上区**改为显示该次执行的日志；不再在行下方内联展开。
- 上区因此有两种模式，由「是否选中某次历史执行」决定（无新增 state 枚举，`selectedRunId: string | null`，`null` 即实时模式）。

### 2. 上区历史模式头部

- 标题替换为「历史执行日志 · <起止时间>」，右侧出现「返回实时」按钮，点按切回实时日志。
- ~~状态徽章 + 日志条数~~ —— **由 ponytail 提案、用户确认砍掉**（与被选中的历史行重复；起止时间已足够定位）。
- 实时模式头部保持现状（标题「实时日志」+ 运行中 run 开始时间 / 重连提示 / 重连失败提示）。

### 3. 实时连接与切换策略

- 切到历史日志时 **SSE 连接保持**，后台继续接收与缓冲（不丢事件）；切回实时立即看到最新。
- 查看历史期间若有新的 `run_started`，**不自动切回**实时，由用户手动点「返回实时」。
- 任务正在执行（实时日志在滚）时**仍允许**随时点开历史执行。

### 4. 日志条目改两行（实时 + 历史都改）

- 第一行：`时间 + 级别`（INFO/WARN/ERROR，保留现有颜色）。
- 第二行：日志内容。
- 实时与历史共用同一个 `LogLine` 组件，统一改。

### 5. 历史行：内联展开 → 选中态

- 移除行下方的内联日志区。
- 选中态：选中行背景高亮（并以 `aria-pressed` 暴露）。~~左侧箭头由「展开态」改为「选中态」（选中 ▾ / 未选中 ▸）~~ —— 2026-09-11 用户反馈「方向键很怪异」，箭头已删除，选中态只靠行高亮。
- 行的其余内容（状态徽章、起止时间、日志条数、截断标记）不变。

### 6. 高度

- 上区由固定 `h-64` 加大到 `h-80`（日志现在只在上区看）；下区占剩余高度并滚动。

## 非目标

- 不改后端、不改任何 API / SSE 事件契约、不改数据模型。纯前端展示层改动。
- 不改上区实时日志的自动跟随 / 「回到最新」/ 重连退避等既有行为。
- 不新增抽象（无 LogSource 接口 / 无 mode 枚举 / 无独立 HistoryLogLine 组件）；复用现有 `LogLine`、`runStatusBadge`、`formatDateTime`。
- 不引入新的日志高亮、搜索、过滤、导出等能力。

## 用户确认

- grilling 两轮 + 收尾确认（共 11 个决策）全部由用户选定，最终回答「是，继续」确认达成共识。
