# REQUIREMENTS — 快照定时任务的运行日志

来源：用户原话（2026-09-10）「现在新建的两个快照定时任务日志太少了，有时候执行成功也没有一条日志，
我没有任何感知。你加一些开始和结束的日志吧，结束日志里再加一些数据。」

## 范围（用户已确认）

1. `stats_snapshot`（统计快照生成）与 `stats_snapshot_rebuild`（统计快照自愈）两个内置任务：
   每次实际执行都留下**开始一行 + 结束一行**日志。
   - 现状：生成任务的增量路径（绝大多数运行）一行不打；首启/时区变更只有「开始回填」没有完成；
     自愈任务只在补算 > 0 时打一行，无缺失时完全静默。
2. 结束日志带本次数据：各粒度（小时/天/月/年）固化桶数 + 耗时；全量回填场景额外带覆盖时间范围。
3. 空转（本次 0 个桶）同样打结束日志——用户的核心诉求是「跑了就要有感知」。
4. 任务内部报错时，run 列表标记「失败」（现在错误只写一行日志、run 仍记成功）。

## grilling 拍板（2026-09-10，一轮 3 问）

| 决策点 | 拍板 |
| --- | --- |
| 结束日志数据 | **桶数 + 耗时**（回填场景加覆盖范围）；否决写入行数（要动生成器返回计数）、否决各级水位（内部细节、噪音） |
| 任务失败语义 | **改为标记失败**：handler 把错误交回 worker（run=failed + 自动追加「任务执行失败：…」）；另两个内置任务本次不动 |
| 测试缝 | **复用 tasks.rs 既有单测缝**：测试用 tracing 捕获层断言日志文本，与现有用例共用 `test_lock` 串行 |

## ponytail 裁剪（已并入上表，无额外待议项）

- 不引入日志框架/结构化字段（JobLogLayer 只捕获 message，字段不会进 UI）。
- 不做日志 i18n（沿用中文，与既有任务日志一致）。
- 不顺手改 `usage_refresh` / `failure_recovery` 的日志与失败语义。

## doc 更新

- 无需 ADR / CONTEXT 词条：日志文本与「错误交回 worker」属既有契约（ADR-0021 生命周期 + worker
  Err→failed 语义）内的实现细节，未产生新的领域词汇或难逆决策。
