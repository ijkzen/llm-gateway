# llm-gateway 使用文档

本文面向 llm-gateway 的使用者（管理后台操作员与 `/v1` API 调用方），按模块说明各项功能怎么用。

llm-gateway 是一个 LLM API 网关：把多家上游供应商（OpenAI Compatible / OpenAI Responses / Anthropic / Gemini 协议）的 API Key 与模型集中管理，聚合成一个 OpenAI 兼容的 `/v1` 入口对外提供。调用方只需一把网关签发的 `lg-` API Key，就能访问网关下所有虚拟模型，并获得负载均衡、故障降级、用量额度门控等能力。

安装与启动（本地 / Docker / Compose）见根目录 [README](../README.md)，本文不再重复。文中「设置时区」指「设置」页的 `timezone` 设置项（首次初始化管理员时选择，默认 `Asia/Shanghai`），统计分桶、用量窗口与定时任务语义都按它解释。

## 1. 快速上手

首次使用按以下顺序走一遍即可完成全部配置：

1. **初始化管理员**：浏览器打开网关地址，首次访问会进入「初始化管理员」页，创建用户名密码，并选择界面语言与时区（时区影响定时任务与统计口径，之后可在设置里改）。
2. **新建供应商**：在「供应商」页填上游 `Base URL`，网关自动匹配已知接入模板并预填协议、付费模式等字段；填入该供应商的 API Key 后保存。
3. **登记供应商模型**：在「供应商模型」页对每个供应商「尝试刷新」拉取远端模型列表（也可从内置目录添加或手动添加），补全上下文长度等字段。
4. **创建虚拟模型**：在「虚拟模型」页把若干供应商模型聚合成一个对外 `display_id`，选择接口类型与负载均衡/降级策略。
5. **创建 API Key**：在「API Keys」页创建一把 `lg-` 密钥交给调用方。
6. **调用验证**：把 API Key 配到你的 OpenAI SDK 里，请求 `POST {网关地址}/v1/chat/completions`，`model` 填虚拟模型 `display_id`：

```bash
curl http://localhost:4007/v1/chat/completions \
  -H "Authorization: Bearer lg-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "my-virtual-model",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

返回即网关选路后上游的回复。之后可在「数据面板」「请求日志」里观测每一次转发的指标。

## 2. 界面结构

管理后台为单页应用，左侧分组导航（顺序即侧边栏顺序）：

| 分组 | 页面 | 用途 |
| --- | --- | --- |
| 概览 | 数据面板 | 请求指标聚合与排行（首页） |
| 概览 | 聊天 | 免 Key 的直连测试对话 |
| 接入配置 | 供应商 | 上游接入（模板/协议/代理/用量） |
| 接入配置 | 供应商模型 | 供应商名下的模型条目 |
| 接入配置 | 虚拟模型 | 对外聚合模型（LB/降级/成员） |
| 接入配置 | API Keys | 调用方凭证 |
| 观测 | 请求日志 | 每次 `/v1` 转发的明细 |
| 管理 | 定时任务 | 内置周期任务（用量刷新/故障恢复） |
| 管理 | 设置 | 系统设置项、修改密码、备份恢复 |

通用元素：

- 顶栏：折叠侧栏按钮、面包屑（仅数据面板详情页出现）、全局「刷新」、语言切换（中文/English）、主题切换（亮/暗/跟随系统）。
- 未登录访问任意页面会跳转到登录页，登录后跳回原页面；会话有效期 7 天，登录状态失效（401）时自动回到登录页。
- 列表/表格页大多支持列显隐、按列排序与分页，个人偏好（如每页条数、隐藏列）保存在浏览器本地。

## 3. 数据面板

### 3.1 首页聚合

首页顶部是 8 张指标卡，分上下两行：

- 上行「全部历史」：累计请求数、请求成功率、总计 Token、缓存命中率（全量累计）。
- 下行「今日」：同一组 4 个指标，但只统计今日（设置时区当天 0 点至今）。

指标卡下方是三个分析区块，各自带独立的时间窗口选择器：

- **调用分析**：三态切换「调用趋势 / 调用次数分布 / 调用次数排行」。趋势为折线；分布为按「供应商・模型」聚合的饼图（Top 10 + 其他）；排行是横向条形图。
- **Token 分析**：同一结构的 token 使用趋势 / 分布 / 排行。
- **性能与可靠性分析**：四个页签——失败诊断（成功/失败堆叠面积 + 失败率折线）、延迟分位（TTFT 与总耗时的 P50/P90/P95/P99）、Token 结构（输入/输出堆叠 + 缓存命中率折线 + 每秒输出 token）、吞吐（RPM/TPM + 流式占比，仅「天」等小时粒度窗口可用，窗口过大时页面会提示）。

页面底部是四张「赛马」排行卡：API Key 赛马、供应商赛马、虚拟模型赛马、供应商模型赛马。每张卡展示指标：总计 Token、请求数、TTFT、平均耗时、TPS、缓存命中率，默认按总计 Token 降序，可点表头换指标与排序方向。**点击排行行会跳转到对应实体的数据面板详情页**（见 3.2），并把当前时间窗口一并带过去。

### 3.2 时间窗口

所有面板共用一个窗口控件，可选「天 / 周 / 月 / 年」或「自定义时间范围」：

- 分段按钮切换粒度；左右箭头切到上一周期/下一周期。
- 「当前周期」截断到当前时刻（如「今天」= 当天 0 点至今），历史周期为完整区间。
- 「自定义」弹窗用本地时间输入起止（默认最近 7 天）。
- 粒度决定统计桶：天→按小时、周/月→按天、年→按月；窗口与桶边界均按设置时区解释。

### 3.3 详情页（二级/三级漏斗）

首页排行行与各列表页的链接会把数据面板下沉到单一实体：

- **供应商数据面板**（供应商页/模型页可进入）：6 指标概览 + 订阅用量卡 + 调用/Token/可靠性分析 + 该供应商内部模型赛马 + API Key 赛马。行点击继续下钻到模型页。
- **虚拟模型数据面板**：同结构（无用量卡），含「成员模型赛马」（显示供应商・模型；停用成员灰显带「（停用）」）。
- **API Key 数据面板**：6 指标 + 分析区 + 按该 Key 过滤的虚拟模型/供应商/模型三张排行。
- **模型数据面板**（叶子页）：单模型 6 指标 + 调用/Token 趋势折线 + 可靠性分析 + API Key 赛马。

详情页顶部面包屑给出回退链（如「数据面板 › 虚拟模型」），标题形如「{名称} · 数据面板」。若实体已被删除，页面会提示不可用并给出返回列表的按钮。

## 4. 聊天

「聊天」页是一个免 API Key 的对话测试台，用于快速验证某个具体供应商模型的连通性与效果（不经过虚拟模型负载均衡，也不触发降级）。

- **选模型**：点输入框上方的模型选择器，弹窗按「已启用供应商」分组列出其供应商模型；选择后对话发送到该模型。
- **发送**：回车发送（Shift+Enter 换行）；响应以 SSE 流式渲染，发送中按钮变为「停止」，可随时中断（该条标记「已停止」）。
- **思考过程**：模型返回思考内容时，消息头部出现可折叠的「思考过程」块，正文开始后自动收起。
- **清空**：右上角「清空对话」。

聊天走管理后台登录会话（Cookie），不消耗 API Key 配额；请求同样会写入请求记录（日志与统计中归属标记为 `chat`），可在数据面板/请求日志中区分。

## 5. 供应商

「供应商」页是左侧列表 + 右侧详情的布局，列表可拖拽排序（决定列表展示顺序）。

### 5.1 新建/编辑

编辑弹窗字段：

| 字段 | 说明 |
| --- | --- |
| Base URL（必填） | 上游地址；创建时输入会自动联想匹配内置接入模板，点「应用」预填名称/协议/付费模式/自定义请求头等 |
| 名称（必填） | 唯一 |
| API Key | 创建时必填；编辑时留空表示不修改（存储加密，详情中默认掩码，眼睛图标/复制按钮按需拉取明文，明文不进缓存） |
| 协议类型 | OpenAI Compatible / OpenAI Responses / Anthropic / Gemini（与上游实际协议一致，决定转发转换与原生端点） |
| 付费类型 | 按量付费 / 订阅制（影响用量卡片形态与 LB 排序策略） |
| 网络代理 | 可选 HTTP 代理地址（`http://` 开头，暂不支持带认证）；模型可单独覆盖 |
| 自定义请求头（JSON） | 高级设置：对上游额外追加的请求头 |
| 用量展示 | 模板支持时出现开关；开启后需填写模板规定的用量字段（CookieCloud / OAuth / AK-SK / 账号密码等，password 类以密码框输入） |

创建后右侧详情展示 Base URL、启用开关、API Key、协议/付费类型、代理状态与时间信息，顶栏名称链接到该供应商数据面板。

### 5.2 用量卡片

供应商**开启了「用量展示」**（`usage=true`）时，详情页出现「用量信息」卡片（供应商数据面板也有）：

- **订阅制**：按厂商提供的窗口展示进度条——5 小时 / 今日 / 本周 / 本月（窗口可用性随厂商），每条显示剩余百分比（绿 >50 / 黄 >20 / 红 ≤20）、已用/限额与重置时刻；底部显示「预估月 Token」（按周用量 × 4 折算）。
- **按量付费**：逐项展示余额条目（金额 + 币种，各厂商字段形态不同，如可用余额/充值余额/赠送余额/欠费等）。

用量数据带缓存（默认约 10 分钟内直接返回上次结果，不会反复请求上游）；点「刷新用量」强制重新抓取。用量判定同时驱动额度门控（见 [第 14 节](#14-自动化行为与故障自愈)）。

### 5.3 其他操作

- **启用/禁用**：右上开关即时生效；**禁用供应商后，其名下模型对 /v1 不可用，虚拟模型中的对应成员显示「随供应商禁用」**。
- **模型测速**：详情菜单「模型测速」对该供应商每个模型发最小化测试请求（固定「你好」提示词），逐行显示耗时，失败给出失败详情；测速请求同样记入请求日志与统计。
- **删除**：确认后删除供应商及其名下全部模型（不可撤销；虚拟模型中的成员随模型删除被级联清理，请先确认影响）。

## 6. 供应商模型

「供应商模型」页按供应商分区展示模型卡片：卡片上为远端模型 ID（可链接到模型数据面板）与能力图标（推理/工具调用/图片理解/视频理解，仅点亮具备项），分区头有该供应商的启用开关与「添加」按钮。页头搜索框按模型 ID 子串匹配并分组展示结果。

### 6.1 添加模型（三种途径，在「添加」弹窗的 Tab 间切换）

- **尝试刷新**（自动添加 Tab）：网关调用上游 Models 接口拉取真实模型列表，并**智能填充**每条候选的上下文长度/最大输出/能力。候选带匹配状态徽标：已智能填充 / 信息不完整 / 需手动填写 / 待确认（「待确认」会给出内置目录里相似度最高的建议，可一键切换预填来源）。勾选后批量添加；刷新失败会弹具体错误。
- **从目录添加**：手动添加 Tab 内，模型 ID 输入框带内置模型目录联想，点选自动填充全部字段。
- **手动添加**：直接填模型 ID（必填）、上下文长度与最大输出（必填正整数）、能力开关与代理设置。

### 6.2 模型详情与编辑

点卡片打开只读详情：所属供应商、上下文长度/最大输出、能力逐项「已支持/不支持」、协议（「跟随供应商」或模型单独指定）、网络代理（模型级优先，否则继承供应商代理）。可在此「测试」（连通性 + 耗时）或进入编辑态修改字段、单独覆盖协议/代理，也可删除（删除会级联清理引用它的虚拟模型成员，确认弹窗有提示）。

> 提示：协议单独覆盖只在特殊混用场景需要；常规做法是保持「跟随供应商」。

## 7. 虚拟模型

虚拟模型是对外暴露的**聚合模型**：多个供应商模型（成员）归到一个 `display_id` 下，网关按策略选路。客户端永远只看到虚拟模型 ID。

### 7.1 创建/编辑

- **虚拟模型 ID**（必填、全局唯一）：客户端 `model` 字段里填的值。**禁用后该虚拟模型不会出现在 `/v1/models` 中**，调用按不存在处理。
- **接口类型**：决定对外用什么端点与哪些成员可用（详见 [13.2 接口类型与端点对应](#132-接口类型与端点对应)）。受限类型（OpenAI Compatible / Responses / Messages / Gemini）只能添加本协议成员；**Full Compatible 接受任意协议成员**，全部经 `/v1/chat/completions` 转换服务。从受限类型切到别的受限类型时，弹窗会列出因协议不匹配将被自动移除的成员并需确认。
- **负载均衡策略**（成员间如何选路）：
  - 订阅制优先：优先选订阅制（套餐）成员；
  - 按量付费优先：优先选按量付费成员；
  - 轮转：按顺序轮流；
  - 随机：随机选择。
  > 对订阅制优先/按量优先策略，若成员供应商开启了用量查询且缓存可用，网关会做**用量感知排序**：订阅制按「额度更早重置/剩余百分比更高」优先、按量按余额更高优先；缓存缺失/过期时才退化为基础排序。
- **降级策略**：直接失败（成员失败立即返回错误）或依次重试其他启用成员（失败后按同一选路逻辑在剩余启用成员里重试，直至成功或全部试完）。
- **启用**：总开关。

### 7.2 成员管理

编辑弹窗内用「已使用 / 未使用」两个 Tab 管理成员（按供应商分组，组头可折叠，供应商停用有警示）：

- 每个成员可单独**启停**（停用后不再参与选路）或**移除**；
- 「继续添加模型」在当前供应商组内展开候选（候选须协议匹配、未被其他虚拟模型占用、未加入）；
- 一个供应商模型**只能归属于一个虚拟模型**，已被占用的模型不会出现在其他虚拟模型的候选中；
- 至少要保留一个启用成员才能保存；修改是暂存的，点「保存」一次性生效。

列表页分区头展示该虚拟模型的徽标（接口类型 / 负载均衡策略 / 降级策略），停用整体带「已禁用」徽标；成员卡片会随供应商停用而显示「随供应商禁用」并降透明度。删除虚拟模型会释放其成员（其他虚拟模型即可再次占用），确认弹窗有提示。

## 8. API Keys

调用方访问 `/v1` 的凭证（`Bearer lg-…`）。表格列：名称（链接到该 Key 的数据面板）、Key（默认掩码如 `lg-****abcd`）、启用开关、创建时间（相对时间显示，悬停可见完整时间），行内操作菜单提供启停与删除。

- **创建**：只需填名称，密钥由系统自动生成；创建成功提示立即保存，之后可随时在列表中点眼睛查看明文或点复制按钮（复制不要求先展开明文）。
- **启停**：停用后使用该 Key 的调用立即返回鉴权失败。
- **删除**：不可撤销，使用该 Key 的调用方立即失效；删除后其历史请求仍保留在日志中（按名称聚合展示，不再可点进数据面板）。

一把 Key 可以调用全部虚拟模型。若想按调用方区分统计，为每个调用方/场景单独建 Key，数据面板与请求日志均支持按 API Key 过滤与排行。

## 9. 请求日志

「请求日志」页记录每一次 `/v1`（含原生端点与测速）转发的明细，服务端分页。

- **表格列**：虚拟模型（缺失显示 #id）、供应商、API Key、上游模型、结果（成功/失败徽章）、输入、输出、耗时、时间；列显隐与每页条数（10/20/50/100）持久化。
- **筛选**：虚拟模型 / 供应商 / 供应商模型（多选，随所选供应商级联、按供应商分组）/ 结果状态 + 时间窗口（默认今天，同数据面板控件）；「重置」一键清空。
- **排序**：默认时间降序，可点表头切换。

点行打开详情弹窗：成功/失败、流式徽章、虚拟模型、供应商、上游模型与完整字段网格——开始/结束时间、总耗时、首 token 耗时（TTFT）、输出耗时、输入/输出/总计 Token、缓存命中 Token、缓存命中率、TPS、请求 ID（`request_id` 的后缀序号可用于对照降级链：同一次调用经多次重试时，`-1/-2` 递减序号相同前缀）。失败请求额外有红色「失败原因」块。弹窗内点击任意字段值可选中复制。

字段口径速览：TTFT = 首 token 耗时（流式，含建连耗时）；TPS = 每秒输出 token；缓存命中率 = 缓存 token / 输入 token。更细口径与排障指南见开发文档。

## 10. 定时任务

内置周期任务（分组 `system`），在「定时任务」页左侧列表中默认选中第一项，右侧为详情。任务**没有新建入口**，只有编辑/启停/立即执行/删除/查看日志。

| 任务 | 默认表达式 | 职责 |
| --- | --- | --- |
| `usage_refresh` | `@every 5m` | 每 5 分钟刷新全部开启了用量展示的供应商用量并落库，执行订阅额度门控（耗尽自动停用/回升自动恢复）与边界实测探活 |
| `failure_recovery` | `@hourly` | 每小时复查因连续失败被熔断停用的供应商，探活通过后自动恢复启用 |

### 10.1 常用操作

- **启用/禁用**：开关即时生效，禁用后不再按计划触发（但仍可手动执行）。
- **立即执行**：立即触发一次（如用量展示异常时可对 `usage_refresh` 点此强制跑一轮）。
- **编辑**：可改标题、分组、描述与 Cron 表达式；任务名不可改。表达式支持标准 5/6 字段 Cron（如 `0 8 * * *` = 每天 8 点，按设置时区解释）、宏（`@hourly` 等）与间隔语法（`@every 5m` / `@every 1h30m`，单位 s/m/h/d 可组合）。
- **查看日志**：弹窗上半是实时日志区（SSE 推送，当前执行中逐条出现，结束显示成功/失败横幅；自动跟随滚动，上滚暂停并出现「回到最新」；断线自动重连），下半是「历史执行（最近 30 次）」，点开某次展开其日志。每次执行最多保留 2000 条日志，超出截断并标记。

> ⚠️ **删除需慎重**：删除后任务从列表消失且**不会因重启自动恢复**（界面也无法重建），需要恢复须人工处理数据。`usage_refresh` 被删除意味着用量不再自动刷新、额度耗尽也不会自动停用/恢复。

## 11. 设置与账号

### 11.1 系统设置项

设置页以键值表列出系统设置（键/值/类型/更新时间），支持搜索与按类型筛选。目前内置 4 个键（其中 `language` 与 `timezone` 禁止删除；其余两个删除后重启会按默认值重建）：

| 键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `language` | String | `zh-CN` | 管理后台语言（zh-CN / en），与顶栏切换等价 |
| `timezone` | String | `Asia/Shanghai` | 时区（IANA 名）：定时任务调度语义、统计分桶与用量窗口均按它解释；修改会按新时区重建定时任务并重算下次执行时间 |

## 13. 客户端接入 /v1 API

### 13.1 端点与鉴权

Base URL 为 `{网关地址}`。管理 API（`/api/*`）走登录会话，**转发 API（`/v1/*`）走 API Key Bearer 鉴权**，两种通道互不相通。

| 端点 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /v1/models` | Bearer `lg-…` | 列出可用虚拟模型（仅启用且接口类型为 OpenAI Compatible / Full Compatible 的虚拟模型，`owned_by=llm-gateway`） |
| `GET /v1/models/{display_id}` | Bearer | 单个虚拟模型；不存在或已禁用返回 404 |
| `POST /v1/chat/completions` | Bearer | OpenAI 兼容主入口：请求体即 OpenAI Chat Completions 格式，`model` = 虚拟模型 `display_id` |
| `POST /v1/messages` | Bearer 或 `x-api-key`（Bearer 优先） | Anthropic Messages 原生透传，仅接口类型 = Messages 的虚拟模型；上游固定带 `anthropic-version: 2023-06-01`；响应为 Anthropic 原生格式（含 SSE 事件类型），适配 Anthropic SDK |
| `POST /v1/responses` | Bearer | OpenAI Responses 原生透传，仅接口类型 = Responses 的虚拟模型；适配 Responses SDK |

> 鉴权失败：`/v1/messages` 返回 Anthropic 原生错误结构，其余端点返回 OpenAI 风格错误结构。`/v1/*` 一律**不**返回管理 API 的 `code/msg/data` 信封（那是 `/api/*` 与聊天页通道的错误格式）。

### 13.2 接口类型与端点对应

| 虚拟模型接口类型 | 客户端用什么调用 | 成员协议限制 |
| --- | --- | --- |
| OpenAI Compatible | `/v1/chat/completions`（OpenAI SDK） | 仅 OpenAI Compatible 协议成员 |
| Full Compatible | `/v1/chat/completions`（OpenAI SDK） | 任意协议成员，网关负责协议转换（推荐混用场景） |
| Responses | `/v1/responses`（OpenAI Responses SDK） | 仅 Responses 协议成员 |
| Messages | `/v1/messages`（Anthropic SDK） | 仅 Anthropic 协议成员 |
| Gemini（预留） | — | 界面中标记为预留 |

即：客户端统一用 OpenAI SDK + `/v1/chat/completions` 时，请建 OpenAI Compatible 或 Full Compatible 类型的虚拟模型；用 Anthropic / Responses SDK 原生接入时，分别用 Messages / Responses 类型。

### 13.3 转发行为与错误

- **选路与降级**：网关按虚拟模型的负载均衡策略在启用成员中选路；开启「依次重试」时，成员失败（本地错误或上游 HTTP ≥ 400）会按同策略在剩余启用成员中继续尝试，直至成功或全部试完；全部失败返回最后一个上游错误（OpenAI 错误信封，`code` 区分 `invalid_request_error` / `api_error` 等）。没有可用成员（如全部成员被停用、或订阅额度全部耗尽被门控）返回 503 `no_available_members`；虚拟模型不存在/禁用返回 404 `model_not_found`；缺 `model` 字段返回 400。
- **超时**：TCP 建连 10 秒、TLS 握手 10 秒；等待响应头 120 秒（流式与非流式一致）；非流式响应体 120 秒；流式响应体不设总超时。
- **流式**：`stream: true` 返回 OpenAI `chat.completion.chunk` SSE 序列，以 `data: [DONE]` 结束；转换链路由网关逐事件转帧（含 `content`/`reasoning_content`/`reasoning_details`/`tool_calls`）。**usage 尾块仅在请求带 `stream_options: {include_usage: true}` 时下发**（与官方 OpenAI 行为一致）。
- **请求头透传**：`/v1/chat/completions` 只把设置项 `downstream_request_header_allow_list` 白名单内的下游头透传给上游（traceparent/tracestate 等链路头可用）；`/v1/messages`、`/v1/responses` 原生透传基本不做头过滤（黑名单兜底），Anthropic 的 `anthropic-beta` 等特性头自然生效。

### 13.4 思考块与多轮续链

网关对三种上游协议（Anthropic / Gemini / Responses）的签名思考载体做**无损透传**：响应里同时给纯文本 `reasoning_content`（展示用）与结构化 `reasoning_details` 数组（携带各厂商 signature / 密文与 `format` 标记，形如 OpenRouter 的 reasoning_details 格式）。直通 OpenAI Compatible 上游时透传上游原生思考字段。

**多轮对话/工具调用的硬要求**：把上一轮 assistant 消息里的 `reasoning_details` 原样带回下一轮请求，网关据此还原上游的 thinking 块 / thought signature，做到跨轮不降智、工具轮不报错。只回传文本会“断链”。若不需要思考内容，可用 OpenRouter 形态的请求参数 `reasoning: {exclude: true}`（或 `thinking`/`reasoning_effort` 按各 SDK 习惯发送）请求网关在响应中剥离思考内容。

### 13.5 一个完整示例（OpenAI SDK）

```ts
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://你的网关地址/v1",
  apiKey: "lg-你的密钥",
});

const stream = await client.chat.completions.create({
  model: "my-virtual-model", // 虚拟模型 display_id
  messages: [{ role: "user", content: "你好" }],
  stream: true,
});
```

多轮时注意把上一轮响应里的 `reasoning_details`（以及需要回传的工具调用结果）原样带回。

## 14. 自动化行为与故障自愈

网关自带一套自动化，多数情况无需人工干预：

- **用量自动刷新与额度门控**：`usage_refresh`（每 5 分钟）刷新全部开启用量展示的供应商（**含被停用的**，持续监测）。订阅制额度任一窗口耗尽（剩余为 0）→ 自动停用该供应商及其名下虚拟模型成员；窗口剩余百分比落在边界区 (0,1)% 时发送最小测试请求实测，失败同样停用；额度回升（离开边界区）或实测成功后**自动恢复启用**。手动「刷新用量」或对 `usage_refresh` 点「立即执行」可加速这一轮判定。
- **连续失败熔断**：某供应商连续失败达到设置项 `max_consecutive_failures`（默认 5）后自动停用；`failure_recovery`（每小时）复查熔断停用的供应商，探活通过后自动恢复。
- **被动降级**：请求级 failover 与以上自动停用是两层机制——前者让单次请求在其他成员间重试，后者长期剔除“病号”供应商。

被额度门控/熔断停用的供应商在列表中带「额度耗尽已停用」等徽章；如需立即恢复，对相应定时任务点「立即执行」触发一轮复检即可，不需要重启服务。

## 15. 术语速查

| 术语 | 含义 |
| --- | --- |
| 供应商（Provider） | 一个上游接入：Base URL + API Key + 协议/付费模式/代理等 |
| 供应商模型（Provider Model） | 供应商名下一个具体的模型条目（如 `gpt-4o`），登记在供应商下 |
| 虚拟模型（Virtual Model） | 对外聚合模型，有自己的 `display_id`，成员来自若干供应商模型 |
| 成员（Member） | 虚拟模型里的一个供应商模型条目 |
| 接口类型 | 虚拟模型对外暴露的协议形态（OpenAI Compatible / Full Compatible / Messages / Responses 等） |
| LB 策略 | 成员选路策略：订阅制优先 / 按量付费优先 / 轮转 / 随机 |
| 降级策略 | 成员失败后：直接失败，或在剩余启用成员中依次重试 |
| 额度门控 | 订阅额度耗尽自动停用、恢复自动启用的机制（quota gate） |
| 熔断 | 供应商连续失败达阈值自动停用（failure），由故障恢复任务复查 |
| TTFT / TPS | 首 token 耗时（流式）/ 每秒输出 token |
| display_id | 虚拟模型的对外模型 ID，客户端 `model` 字段填它 |
