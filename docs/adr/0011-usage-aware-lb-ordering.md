# 0011 — 用量感知 LB 选路排序与剔除口径（选路序与成员展示序同源）

## Status

accepted

## Context

虚拟模型 LB 策略 0/1（订阅制优先/按量付费优先）需要组内排序。早期按剩余百分比排序，后来发现订阅额度有截止时间维度：同样的剩余量，临近重置的额度不及时用掉会作废，因此排序演进为「截止时间优先（FEFO）」。排序与「该成员能否参与选路」的剔除判定必须口径一致，且接口展示的成员顺序应与 LB 实际尝试顺序一致，否则「所见非所用」。

## Decision

1. 比较器收在 `src/proxy/usage_rank.rs`（纯函数，直测）：
   - 订阅制 `cmp_quota_deadline_priority`：从 5h 层起逐层检查双方该层都有额度（剩余 > 0 且窗口 available），有则跳过剩余百分比、改比更上层（日/周/月）截止时间——早重置者优先、缺截止时间者排后；截止链全平回退剩余百分比逐层比较（5h→日→周→月，同层打平比该层重置时间）；层内无额度/窗口不可用判平进下一层；全平随机选一。
   - 按量付费 `cmp_balance`：按 fetcher 标记的主余额字段（`BalanceItem.primary`，单字段不做合计）降序。
   - 窗口级「同类取最差剩余」与可用判定共用 `UsageData::worst_window` 单一扫描（`subscription_usable`/`balance_usable` 建其上），排序逐层判定与全局可用两口径一致性由矩阵测试锁定。
2. 剔除口径先于排序：订阅制 `subscription_usable()` 为 false（任一已提供窗口剩余为 0）即剔除；按量 `balance_usable()` 为 false（查得到且合计为 0）即剔除，查不到余额的成员**不剔除**（无法判定视为可用，避免上游抖动误伤）。剔除后的顺序即 failover 尝试顺序；降级策略=1 时每次失败在剩余成员中按同策略重新选路。
3. 用量数据优先取 10 分钟数据库缓存，缺失/过期才真实抓取；策略 2/3（轮转/随机）回退静态序。
4. 成员展示序与选路序同源：GET 列表/详情与 POST/PUT 响应统一为「启用 → 策略分组 → 组内用量排序 → 平局/无数据按条目 id 升序」；展示不剔除耗尽成员、不随机化；编辑弹窗保持该序。

## Consequences

- 先到期先用的 FEFO 减少订阅额度作废浪费；调度、展示、编辑三处看到同一顺序。
- 剔除/可用判定单一来源（`worst_window`），门控（ADR-0010）与选路不会打架。
- 比较器直测 + LB 链路集成测试锁定口径；口径改动只落 usage_rank 与 usage/types。

规格：`.scratch/subscription-deadline-priority/`。
