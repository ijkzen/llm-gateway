# 0017 — 配置备份导出与恢复（整体替换）

## Status

accepted

## Context

管理后台的全部配置（供应商、模型、虚拟模型及成员、API Key、系统设置）需要可导出迁移与灾备恢复。恢复语义的分歧点在于「合并还是替换」：合并会留下目标库残留脏数据（旧供应商/成员），无法还原到与导出时等价的状态。

## Decision

1. `GET /api/backup/export`：全量导出供应商（**明文 api_key/extra**）、各供应商模型、虚拟模型及成员、API Key（明文）、系统设置，`version:1` JSON。导出文件即敏感载体（含全部上游凭据），须安全保管——这是有意的取舍：备份必须能脱离原库密钥恢复。
2. `POST /api/backup/import`：单事务**整体替换**上述配置（先清后插、主键重建映射）；系统设置只 upsert 覆盖、不删除；结构级校验（自然键唯一/引用可解析/成员协议匹配）+ 值级校验（复用各业务路由的 extra/proxy/协议枚举/设置声明类型校验口径）；任一失败整体回滚。
3. 前端设置页提供备份入口：导出/恢复弹窗、导入破坏性确认、错误明细弹窗（zh/en）。

## Consequences

- 恢复后与导出时状态等价（整体替换而非合并）；导入失败零副作用（事务回滚）。
- 明文凭据只在导出文件出现一次，导入时经统一写入口重新加密落库（ADR-0002 不变式不破坏）。
- 校验复用业务口径：绕过业务表单的非法配置同样被拒，导入不能成为旁路。

规格与测试：`.scratch/backup-restore/`、`src/backup.rs`。
