# 0020 — 虚拟模型域不变量：互斥映射、可用性组合与策略语义

## Status

accepted

## Context

虚拟模型是对外暴露层（`display_id` + 成员聚合 + 策略），其域不变量（互斥映射、条目可用性组合、级联语义、策略如何执行）散落在 entity 约束、路由级联逻辑与 LB 选路之间，早期成文于虚拟模型功能开发，无评审拍板记录。本文按现状固化这些不变量，作为管理 API、选路与前端展示共享的契约（接口类型/端点对应见 ADR-0005，用量感知排序见 ADR-0011，级联状态机见 ADR-0003）。

## Decision

1. **标识与对外可见性**：`display_id` 全局唯一，是 `/v1` 对外的模型标识；虚拟模型禁用即不出现在 `/v1/models`，单查按 404。接口类型 `interface_type`（0=OpenAI Compat / 1=Responses / 2=Messages / 3=Gemini 保留 / 4=Full Compatible）：`/v1/models` 列表与单查只出 0/4（chat/completions 可服务），端点×类型严格对应见 ADR-0005。
2. **互斥映射**：一个供应商模型最多归属一个虚拟模型（`uq_virtual_model_items_model_id` 唯一索引，迁移 6）；已被占用的模型不出现在其他虚拟模型的可选候选列表；删除虚拟模型即释放其成员（成员随之删除）。
3. **成员可用性组合**：条目实际可用 = 条目启用 ∧ 供应商 traffic-eligible（availability 读侧谓词，ADR-0003）∧ 成员协议匹配（生效协议 = 模型级 `protocol_type` 覆盖（迁移 20，空则回落供应商）→ 供应商）。接口类型变更/协议变更级联硬删不匹配成员（Full Compatible 豁免，ADR-0005）。级联停用打 `cascade_disabled` 标记；级联恢复只动带标记条目——用户手动关闭的成员不被自动恢复（ADR-0003 的 `set_items_enabled` 语义）。
4. **策略语义**：LB 0/1 = 订阅制优先/按量付费优先（组内用量感知排序，含剔除口径，ADR-0011）；2/3 = 轮转/随机（回退静态序）；降级策略 0 = 失败直接返回；1 = 依次尝试本虚拟模型内其余被启用成员（每次失败后在剩余成员中按同策略重选，ADR-0011/0012），空候选返回 503。成员展示序与选路序同源（ADR-0011），排行行主键化、已删行禁点（ADR-0016）。

## Consequences

- 域规则单点可查：互斥由唯一索引兜底、级联由 availability 动作统一、匹配由类型/协议矩阵判定，杜绝「半可用」意外状态。
- 管理 API 与选路共享同一成员集合语义——改类型/停供应商的效果在列表、展示与转发三处一致。
- 策略演进只动 LB 层（usage_rank/attempt 循环），entity 与管理路由不随之改动。
